## 2. MVC 分层规则(核心红线)

### 2.1 三层职责定义

| 层 | 命名空间/目录 | 职责 | 允许依赖 |
|---|---|---|---|
| **Model** | `Scripts/Models/` | 纯 C# 运行时数据 + ScriptableObject 静态配置 | 仅 .NET BCL、`UnityEngine` 中的 `[CreateAssetMenu]` 等 SO 基础设施 |
| **View** | `Scripts/Views/` | UGUI 展示,只订阅事件刷新,不写玩法逻辑 | `UnityEngine.UI`、EventBus |
| **Controller** | `Scripts/Controllers/` | 挂载场景实体驱动玩法 | Model、EventBus、`UnityEngine` |
| **Core** | `Scripts/Core/` | 框架层(GameManager / EventBus / ObjectPool / GameStateMachine) | `UnityEngine` |

### 2.2 分层红线(违反即返工)

- ❌ **Model 层禁止引用任何 `MonoBehaviour` 子类**。`GameModel` 是纯 C# 类,只持有值类型与 `FishDef`(SO 引用可,但不可调用其游戏逻辑)。
- ❌ **View 层禁止主动查询玩法状态**。HUD/Result/Tutorial/Pause 只能通过 `EventBus.Subscribe<T>()` 接收事件后刷新,禁止 `Update()` 里轮询 Model。
- ❌ **Controller 层禁止直接调用 View 方法**。跨层通信只能走 EventBus。
- ❌ **Model 不发命令,Controller 不存数据**。数据流向必须单向:`Controller → Model(写) → EventBus(广播) → View(刷显示)`,反向 `View → EventBus → Controller` 仅限玩家指令(按钮点击、技能请求)。
- ✅ 允许的解耦收益:改 UI 不动逻辑、加功能不碰旧代码、Model 可直接序列化做存档/热更。

## 3. 六大设计模式落点(必须每条实现)

### 3.1 状态机模式(State)

**落点**:`Scripts/Core/GameStateMachine.cs` + `Scripts/Controllers/States/*.cs`

**规则**:
- 状态基类 `GameState` 抽象方法:`OnEnter() / OnUpdate() / OnExit()`。
- 状态机驱动器持有 `GameState Current`,每帧调用 `Current.OnUpdate()`。
- 切换流程:`Current.OnExit()` → `Current = next` → `Current.OnEnter()`,切换必须通过 `EventBus.Post<PhaseChangedEvent>()` 广播。
- **状态内的逻辑写在状态类里,跨状态的协调走 EventBus。** 不允许在 Controller 里用 `if (state is DescendingState)` 之类做分支。
- 同一事件在不同状态语义不同的核心例证:
  - `DescendingState.OnHookHitFish()` = 捕获该鱼 + 切换到 `AscendingState`
  - `AscendingState.OnHookHitFish()` = 捕获该鱼 + 继续(满 10 触发 4 倍速)

### 3.2 观察者模式(Observer)

**落点**:`Scripts/Core/EventBus.cs`(单例,挂 `DontDestroyOnLoad`)

**规则**:
- 实现 `void Post<T>(T evt)` 与 `void Subscribe<T>(Action<T> handler)`,内部用 `Dictionary<Type, Delegate>` 维护订阅者。
- 必须提供 `Unsubscribe<T>()`,所有 View 在 `OnDisable/OnDestroy` 必须退订,否则会内存泄漏。
- 所有跨层通信必须走 EventBus,**禁止 Controller 直接调用 View 方法、禁止 View 直接读 Model 字段**。
- 标准事件命名:`XxxChangedEvent`(数据变更)、`XxxCommandEvent`(玩家指令)、`XxxTriggerEvent`(玩法触发)。例:`DepthChangedEvent`、`FishCaughtEvent`、`PhaseChangedEvent`、`SkillRequestCommand`、`RoundEndEvent`。
- 事件类必须定义为 `readonly struct` 或简单 `class`,字段只读,避免事件被中途篡改。

### 3.3 对象池模式(Object Pool)

**落点**:`Scripts/Core/ObjectPool.cs`(通用)+ 鱼种分桶 `Dictionary<FishDef, Queue<FishController>>`

**规则**:
- 鱼按预制体/`FishDef` 分池,**不可一锅烩**(否则回收时无法重置 FishDef 引用)。
- `Spawn()` 优先取池;池空时 `Instantiate` 并 `SetUp(def)`;`Despawn()` 重置位置、速度、行为状态后入池。
- 钩子挂载的鱼(已捕获)**不走池回收**,直到结算后统一 `DespawnAll()`。
- 必须提供 Debug 快捷键打印各池 `active/inactive` 数量,重开 20 局后池内数量应完全归位。
- 鱼预制体同屏上限建议 15 条,池容量预估 100。

### 3.4 策略模式(Strategy)

**落点**:`Scripts/Controllers/Behaviors/IFishBehavior.cs` + `PatrolBehavior.cs` / `DriftBehavior.cs` / `SnakeBehavior.cs`

**规则**:
- 接口 `IFishBehavior` 必须含 `void Tick(FishController fish, float dt)`。
- 行为由 `FishDef.BehaviorType` 枚举决定,`FishController` 不持有具体行为判断,只调用 `behavior.Tick(this, dt)`。
- 新增鱼种行为 = 新建一个 `IXxxBehavior` 实现 + 在 `FishDef` 行为枚举里加一项 + 工厂按枚举选实现,**FishController 主逻辑零改动**。
- 三种必备实现:
  - `PatrolBehavior` — 水平直线巡游(小银鱼/小红鱼/蓝绿条纹鱼)
  - `DriftBehavior` — 原地漂浮/缓慢移动(河豚)
  - `SnakeBehavior` — S 型蛇形游动(深海带鱼)

### 3.5 工厂模式(Factory)

**落点**:`Scripts/Controllers/FishFactory.cs`

**规则**:
- `FishFactory.Spawn(FishDef def, Vector2 pos)` 内部决定走对象池还是新建,**调用方不知道对象池存在**。
- 创建细节(实例化、挂行为、应用 Sprite/尺寸、配置碰撞体)全部封装在工厂内,`SpawnerController` 只负责"在哪里、什么深度生成什么 FishDef"。
- 工厂按 `FishDef.BehaviorType` 通过 switch/字典映射到对应 `IFishBehavior` 实现并注入 `FishController`。
- 新增鱼种时:`FishDef.asset` + (如需新行为)新 Behavior,工厂代码**零改动**或仅扩展枚举映射。

### 3.6 单例模式(Singleton)

**落点**:`Scripts/Core/GameManager.cs`、`Scripts/Core/EventBus.cs`

**规则**:
- 仅允许 `GameManager` 与 `EventBus` 使用单例,且必须 `DontDestroyOnLoad`。
- 单例实现用 `public static EventBus Instance { get; private set; }`,在 `Awake()` 中赋值并做唯一性校验(`if (Instance != null) { Destroy(gameObject); return; }`)。
- **禁止滥用单例**:`HUDView`、`ResultView`、`HookController` 等不得是单例,应通过 EventBus 通信。
- 不引入 DI 框架,规模小用单例反而干净。

## 7. 输入抽象规则(对应需求 3)

- 必须定义 `IInputService`,对外只暴露 `event Action<Vector2> OnDragDelta`。
- `MouseInputService`(Editor 用 `Input.mousePosition`)与 `TouchInputService`(真机用 `Input.touches`)各一个实现。
- `InputBootstrap` 按平台自动挂对应实现(`#if UNITY_EDITOR || UNITY_STANDALONE` 用鼠标,否则触摸)。
- **禁止在 Controller 里直接调 `Input.*`**,所有输入必须经 `IInputService`。
- 扩展重力感应只需新增一个实现类,零改动接入。

## 8. 注释规范(明说的加分项)

- **每个类头部必须写职责注释**:一行说明该类做什么、属于哪层、解决了什么问题。例:
  ```csharp
// HookController:玩家操控核心,挂载鱼钩实体。负责下潜/上升移动、碰撞分发、鱼获挂载成串。
// 属于 Controller 层,通过 EventBus 与 Model/View 通信。

- **公开方法必须写 `<summary>`**,说明用途、参数含义、副作用。

- **状态类**头部需注明该状态对应视频哪个阶段、进入/退出条件。
- 禁止保留 `// TODO` 在交付版代码中 —— TODO 全部移入 README「已知限制」。

## 10. 重开逻辑统一入口

- **必须**有 `GameModel.Reset()` 作为单局重置的唯一入口,内部清空捕获字典、重置深度、技能次数、货币累计标志。
- **禁止**在多个 State 或 Controller 里散落重置代码。
- 重开流程:`SettlementState` 玩家点"继续体验" → `EventBus.Post(new ResetCommand>()` → `GameManager` 调 `GameModel.Reset()` → 切到 `CountdownState`。
- 鱼全部回池由 `SpawnerController.DespawnAll()` 在 `ResetCommand` 时触发,与 Model 解耦。

## 12. 编码风格补充

- 一律使用 C# 6+ 语法,自动属性、字符串插值 `$""`、表达式体成员可用。
- 文件命名与类名一致,一个文件一个 public class(允许多个 internal 辅助类)。
- `using` 在文件顶部,按 System → UnityEngine → UnityEditor → 项目内命名空间分组排序。
- 大括号:Allman 风格(左括号另起一行),与 Unity 官方示例保持一致。
- 缩进:4 空格,不用 Tab。
- 字符串字面量:中文文案直接用 UTF-8,不用 `\u` 转义。
